# Приложение D01. `analysis/REPORT_RU.md`

**Дословный исходный отчёт.** Даты/статусы/неизвестные роли внутри относятся к своему этапу. При расхождении использовать актуальный свод и поздние доказательства. Пути внутри текста — исторические: соответствующие материалы встроены в MD/CPP и находятся через поиск исходного пути.

# Neverlose CS2: результаты статического разбора дампа

## Статус результата

Это **частичная реконструкция по фактическим байтам**, а не восстановленные исходники и не полный набор rage-функций. Найдена и разобрана реальная цепочка подготовки aim/fire-команды. Полная логика target selection, hitchance, damage/penetration, lag compensation, resolver и всех сопутствующих режимов **пока не восстановлена**. Исходные имена функций и полноценные типы отсутствуют; `FUN_<VA>` — имена, присвоенные инструментом.

Получены Ghidra-проект, C-подобный псевдокод выбранных функций, дизассемблирование, индекс ссылок и воспроизводимые скрипты. Сам DLL/дамп ни разу не запускался, не инжектировался и не модифицировался. Ghidra и анализаторы выполнялись только как инструменты статического чтения. Восстановление лицензирования/создание рабочего кряка в этот результат не входит.

## 1. Что проверено в файле

| Параметр | Результат |
|---|---|
| Входной архив | `cs2_212C3300000.rar`, RAR5, 42 578 727 байт |
| Содержимое | Один файл `cs2_212C3300000.bin` |
| Размер распакованного файла | 83 890 176 байт = `0x5001000` |
| SHA-256 BIN | `3224604483481c57a18ccfb20448a5e634a9583421abfac3a2712bba5cc77f27` |
| SHA-256 RAR | `763e580f9827c46c23eb5e5b9e33ec643d7ee9221d2b91083ef1f623989cfd87` |
| Модель адресации | Линейный memory dump: `RVA = file offset`, `VA = 0x212C3300000 + RVA` |
| Заголовки | PE-заголовок не распознан; файл не начинается с `MZ`. Первые `0xA00` байт нулевые |
| Архитектура анализа | x86-64, Windows compiler specification |
| Заявленная точка входа | VA `0x212C82F1690`, RVA `0x4FF1690`; по этому адресу есть осмысленная init-обёртка |
| Идентичность | Строка `neverlose_cs2.dll`, несколько путей `neverlose\\neverlose-cs2` и соответствующие particle assets; это согласованные признаки, не независимая проверка подлинности |
| Версия продукта | Не установлена; версии LuaJIT/OpenSSL не являются версией Neverlose |

База взята из сообщения пользователя, не из отсутствующего PE-заголовка. Прямые RIP-relative ссылки, таблица unwind и предоставленные слоты импортов согласуются с этой моделью. Обозначение «pre-entry» — предоставленная характеристика, а не независимо доказанный момент снятия дампа. Нулевые страницы сами по себе не означают повреждение: среди них могут быть BSS и незаполненные области.

## 2. Объём реального анализа

- Структурно восстановлена непрерывная таблица, похожая на x64 `RUNTIME_FUNCTION`, в RVA `[0x3F454F0, 0x3FC955C)`: **45 065 записей, 45 064 уникальных begin RVA**. Одна пара begin/end повторяется с другим unwind RVA. Запись unwind — не обязательно отдельная исходная функция; возможны cold fragments, chained entries и большие защищённые диапазоны.
- Индексировано **2 801 900 инструкций и 509 768 RIP-relative/direct-branch ссылок**. SQLite хранит RVA, не абсолютные VA.
- Linear Capstone полностью прошёл **43 604 из 45 064** уникальных диапазонов. В остальных он останавливался на нераспознанных байтах. Поэтому отсутствие записи в индексе **не доказывает** отсутствие вызова или чтения. Register-indirect calls и функции без unwind-метаданных тоже не полностью покрыты.
- Вручную отобраны **22 функции/диапазона для Ghidra**, у **21 получен псевдокод**. Диапазон `0x767530` достиг лимита декомпиляции 45 секунд; его дизассемблирование сохранено. Это не попытка декомпилировать все 45 тысяч диапазонов.
- Перенесены **391 импорт из предоставленной таблицы**, в трёх областях `321 + 67 + 3`, 11 модулей. Все слоты содержат внешние адреса с верхней частью `0x7FFD`. Имена импортов являются сведениями пользователя; без соответствующих внешних DLL они не проверены как реальные exports. Отсутствующие строки таблицы не выдумывались.
- Компактный каталог содержит 299 строковых свидетельств, 43 anchor-записи, 220 RTTI-looking имён и 58 protobuf-полей. Каталог не является списком реализованных функций.

## 3. Подтверждённый фрагмент aim/fire-логики

**VA `0x212C380FB10`, RVA `0x50FB10`** — наиболее содержательная найденная функция. Важна совокупность операций, а не наличие одного RandomFloat. Исходное имя неизвестно; рабочее описание: подготовка углов, временных записей и атаки.

### Последовательность

1. Копирует сохранённое состояние через `0x511D50`: destination берётся из `this+0x1F0`, source — `this+0x2B8`.
2. Обрабатывает пару `integer tick + fractional tick` из `this+0x6C4`/`this+0x6D0`: `modff`, перенос дробной части через границу 1, выбор ограниченной временной пары относительно другого tick (`this+0x680`). Верхняя дробная граница — ближайший float ниже 1: `0.9999999403953552`.
3. Использует переданные готовые углы либо вычисляет направление от одной точки к другой:

```text
delta = target_point - origin_point
yaw   = atan2(delta.y, delta.x) * 180/pi
pitch = atan2(-delta.z, sqrt(delta.x² + delta.y²)) * 180/pi
wrap(angle) = angle - 360 * floor(angle/360 + 0.5)
```

Для вертикального направления имеется отдельная ветка. Роль внешнего математического указателя установлена по аргументам и формулам, а не по прочитанному коду внешней DLL.

4. Получает две прогнозируемые угловые поправки через `0x3375A0` и в отдельных режимах вычитает их из углов. В helper найдены кэширование, затухание, скоростной вклад с шагом `1/128` секунды и quaternion-based интерполяция; подробности — `review_rng/addendum_vector_sampling.md`. **Назвать производителей этих состояний именно recoil/punch без проверки происхождения данных нельзя.** Есть также выбор из таблицы углов; значения таблицы в этом снимке не инициализированы.
5. Формирует запись истории с размером элемента **`0xAC`**: углы, временные пары, флаги присутствия. В отдельных ветвях заменяет tick/subtick через другой helper.
6. В одной ветви применяет RandomFloat к **времени**, а не к spread:

```text
upper_seconds = min(weapon_related_value, 0.1)
lower_seconds = max(upper_seconds - 0.05, 0)
delta_ticks = RandomFloat(lower_seconds, upper_seconds) * 64
```

Это восстановленный поток данных. `64` здесь — коэффициент перевода секунд в ticks, **не число hitchance samples**. Назначение поля `weapon_related_value` и исходное название режима не установлены.

7. Имеется отдельная ветка записи ограниченных углов: pitch `[-89,+89]`, yaw `[-180,+180]`, roll 0. Совместимость с visible/silent-aim разделением — гипотеза, не восстановленное название настройки.
8. Выбирает маску `1` либо `0x800`, согласующуюся с primary/secondary attack, связывает атаку с индексом history, фильтрует/добавляет subtick press records размером **`0x48`**, учитывает лимит 32 и специальный item code `0x40`.

Эти операции подтверждают **aim/fire-command staging**, но не весь ragebot и не автономный алгоритм серверной lag compensation.

### Где проверять

- Псевдокод: `decompiled_rng/212c380fb10.c`.
- Полный выбранный Ghidra listing: `ghidra_assembly/212c380fb10.asm` (точное имя см. `functions.tsv`).
- Разбор математики и конкретные инструкции: `review_rng/summary.md`, раздел 2.
- Вызов из крупного caller: RVA `0x506787`, владелец `0x505F50`; его псевдокод — `decompiled_features/212c3805f50.c`.
- Нижняя часть функции находится за `0x5105B8`, где линейный Capstone остановился. Для неё ориентироваться на Ghidra/байты, не на полноту SQLite.

### Дополнительный проход по caller и истории

См. `CORE_ADDENDUM_RU.md`: в `0x505F50` установлен выбор candidate из записей `0x30`; в `0x52B250` — отбор до двух пространственно-временных записей из 16-слотового кольца (`0x500` на слот), с фильтрами distance/time и двумя directional группами. Это подтверждённые фрагменты обработки history, но не полный алгоритм lag compensation. `0x309500` обрабатывает отдельное 32-слотовое кольцо временных пар. Для `0x528B90` сохранены предупреждения Ghidra о некорректном/неполном control flow.

## 4. Восстановленный layout helper копирования

**VA `0x212C3811D50`, RVA `0x511D50`**: копирование структуры со скалярными областями и двумя динамическими массивами.

| Offset в объекте | Наблюдаемое поведение |
|---|---|
| `[0, 0x5C)` | Копирование скалярных байтов, перекрывающимися SIMD загрузками/записями |
| `+0x60/+0x68/+0x70` | begin/end/capacity-подобная тройка; размер элемента `0x48` |
| `+0x78/+0x80/+0x88` | Вторая тройка; размер элемента `0xAC` |
| `[0x90, 0xBA)` | Копирование хвостовых полей |
| `+0xB6/+0xB7/+0xB8` | Сохраняются прежние байты destination, затем восстанавливаются после копирования |

Проверяется capacity, при необходимости вызывается allocator helper, обновляется end. При `dst==src` глубокое копирование массивов пропускается. Названия структур не восстановлены; называть этот helper «копированием lag record» только по двум массивам нельзя.

## 5. Что отсеяно как ложные совпадения

| VA / RVA | Результат |
|---|---|
| `0x212C3F421C0` / `0xC421C0` | Setter `spread`, `flip_sign`, `flip_y`, `overlaps`: совпадает с FreeType SDF properties, не weapon spread |
| `0x212C3F422B0` / `0xC422B0` | Соответствующий getter этих свойств |
| `0x212C35E9B50` / `0x2E9B50` | Два пространственных конца эффекта, RGB/alpha ×255, lifetime и варианты ресурсов. RNG и sin/cos не делают эту функцию hitchance |
| `0x212C3722970` / `0x422970` | UI выбора из пяти интервалов, RandomFloat внутри выбранного интервала. Конкретное поле настройки не установлено |
| `0x212C3706C10` / `0x406C10` | UI-значение: `quotient*10000 + RandomInt(0,9999)`; не hit simulation |
| `0x212C3A1EBE0` / `0x71EBE0` | UI transition/reset, случайные компоненты ±0.08 |
| `0x212C384BC60` / `0x54BC60` | В основном shot-result/status formatting и уведомления, но есть дополнительные изменения состояния; не объявляется pure UI |
| `0x212C37FD710` / `0x4FD710` | Выбор строки из hash lookup/массива; автоматический C-псевдокод существенно неточен, см. ASM и review |

Сопоставление FreeType: https://raw.githubusercontent.com/freetype/freetype/master/src/sdf/ftsdfrend.c — одинаковые свойства, порядок условий и поведение setter/getter. Подробности: `results/freetype_evidence.txt`. Точная версия библиотеки этим не определяется.

Строки `records` в DXBC shader metadata относятся к trajectory/tracer buffers. `input_history`, `cl_interp`, `player_tick_fraction`, `random_seed` в protobuf-схемах показывают формат данных, но сами по себе не доказывают ни backtrack, ни resolver, ни hitchance.

## 6. Что НЕ восстановлено

| Подсистема | Реальный статус |
|---|---|
| Aim/fire command preparation | Частично восстановлена указанная функция; имеются неразрешённые типы, callees и режимы |
| Target selection / hitbox scan / multipoint | Полная политика и все ветви не установлены |
| Hitchance / weapon spread | Подтверждённый самостоятельный расчёт не выделен; RNG UI и RNG времени исключены как ложные доказательства |
| Damage / penetration / autowall | Не восстановлены |
| Lag-record storage / validation / rewind / interpolation policy | Частично восстановлен отбор исторических записей; запись/удаление, rewind/restore и полная политика не восстановлены |
| Resolver / anti-aim / tickbase / rapidfire / defensive | Наличие и полная логика соответствующих режимов этим проходом не установлены |
| Полный список rage UI и Lua API | Не восстановлен; многие текстовые совпадения относятся к библиотекам и схемам |
| Исходные C++ классы и ABI всех методов | Не восстановлены |
| Рабочая DLL / эквивалентная компилируемая реализация | Не созданы |

Нет оснований ни утверждать отсутствие перечисленных подсистем, ни заполнять пробелы «типичным кодом CS2». Pre-entry снимок и отсутствие runtime heap/context ограничивают подтверждение динамических таблиц. Значительная часть указателей обращается за пределы данного образа. Это не доказывает, что дальнейший статический разбор невозможен, но **полное покрытие не достигнуто**.

## 7. Как пользоваться материалами

- Начать с этого отчёта, затем `review_rng/summary.md` и выбранных `.c`/`.asm`.
- `results/code.sqlite`: таблицы `functions(begin,end,unwind,table_rva,decoded_end,instruction_count)` и `refs(source,target,owner,mnemonic,operands,kind)`. Все численные адреса в БД — RVA. `end` — exclusive.
- `imports/user_imports.csv`: полная предоставленная таблица, без молчаливого дополнения.
- `strings/summary.md`, `anchors.csv`, `schema_fields.csv`: строки и метаданные; оценка `spread` в строковом отчёте предварительная и уточнена выше по коду.
- `scripts/RecoverDump.java`: загрузка import labels, выбранных string anchors, ограниченных функций и декомпиляция. `scripts/ExportEvidence.java`: сохранение listing без исполнения образца.
- Ghidra-проект импортирован как raw binary в базе `0x212C3300000`, `x86:LE:64:default`, Windows. Auto-analysis всего образа намеренно не выдаётся за выполненный.
- Ghidra `.c` — **псевдокод, не готовые исходники**. `undefined*`, `extraout_var`, AVX intrinsics, `UNRECOVERED_JUMPTABLE` и предупреждения отражают потери типов/CFG. Не компилировать эти файлы как эквивалент оригинала.

## 8. Следующие конкретные точки разбора

Проследить caller `0x505F50`, источники временных/векторных состояний для `0x50FB10`, `0x3375A0` и его производителей; восстановить hash/config bindings, непрямые переходы и происхождение динамических таблиц. Отдельно установить record validation/rewind и hit tests, затем доказывать policy target selection/hitchance/damage по CFG и данным. Только после этого можно проверять полноту набора функций.

Post-initialization snapshot с контекстом объектов мог бы помочь проверить динамические значения, но он не заменяет статический разбор и сам по себе не гарантирует восстановление всех функций.
