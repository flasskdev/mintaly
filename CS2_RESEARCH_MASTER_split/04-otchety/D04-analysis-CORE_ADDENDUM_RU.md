# Приложение D04. `analysis/CORE_ADDENDUM_RU.md`

**Дословный исходный отчёт.** Даты/статусы/неизвестные роли внутри относятся к своему этапу. При расхождении использовать актуальный свод и поздние доказательства. Пути внутри текста — исторические: соответствующие материалы встроены в MD/CPP и находятся через поиск исходного пути.

# Дополнение: выбор кандидатов и временных записей

Это продолжение частичной реконструкции; имена ролей аналитические. Все адреса RVA переводятся в VA прибавлением `0x212C3300000`. Числа/поля ниже получены из байтов и подтверждённых ветвей, а не из типового кода другого чита.

## 1. Caller `0x505F50`: выбор до применения aim/fire

VA `0x212C3805F50`, псевдокод `decompiled_features/212c3805f50.c`.

Перед вызовом `0x50FB10` на RVA `0x506787` перебирается массив записей **`0x30` байт**, begin/end в `this+0x7AC0`/`this+0x7AC8`. Сравнение использует:

- флаг записи `+0x10`;
- integer score в `+0x0C`;
- флаг `+0x14` объекта по указателю из записи `+0x18`;
- дополнительный флаг записи `+0x11`.

По ним выбирается одна запись и передаётся в найденный финализатор команды. Точное значение score — damage, priority, иной показатель — **не установлено**. Из этого сравнения нельзя выводить полную политику target selection и названия UI-настроек.

В предшествующих циклах вызываются `0x50DD90`, `0x52B250`, `0x528B90`. Их C-псевдокод сохранён в `decompiled_core/`. Для `0x528B90` Ghidra выдал предупреждения о плохих инструкциях и переходах к отсутствующей памяти (`0xEB`, `0xCB`, `0x6B`, `0x4B`). Статус `ok` означает лишь получение текста: он **не** подтверждает правильный CFG или семантику всех ветвей.

## 2. `0x52B250`: отбор из 16-слотовой истории

VA `0x212C382B250`, `decompiled_core/212c382b250.c` и `ghidra_assembly/212c382b250.asm`.

### Устройство

- Число записей: объект `+0x50F0`.
- Индекс/начальная позиция: `+0x50F4`.
- Слоты: объект `+0xF0 + slot*0x500`, кольцевая индексация по 16 слотам.
- Начало слота: integer tick в `+0`, fraction в `+4`.
- Позиция: `+0x14/+0x18/+0x1C` относительно слота.
- Два используемых угла: `+0x44/+0x48` относительно слота.

Это положительное свидетельство работы с **историей пространственно-временных записей** на пути к aim/fire. Исходное имя класса и назначение остальных байтов записи не установлены.

### Фильтры и выбор

1. Очищает выходной vector begin/end (`RVA 0x1754AC8/0x1754AD0/0x1754AD8`). Сам массив может находиться вне dump после инициализации.
2. Перебирает записи кольца, строит горизонтальное направление и вектор из углов, добавляет временную поправку из отдельного singleton.
3. Проверяет squared distance до переданной точки: порог **62 500** (геометрический радиус 250 единиц при обычной евклидовой интерпретации). Константа RVA `0xE9BB50`, bytes `00 24 74 47`; сравнение RVA `0x52B4B1`.
4. Проверяет абсолютную разницу времени: перевод ticks в seconds множителем **1/64** (RVA `0xE98AC0`), затем ×**1000** (RVA `0xE9AC44`), truncation к integer и отклонение, если integer больше **200** (`CMP ECX,0xC8` на RVA `0x52B553`, `JG` на `0x52B559`). Это **целочисленно-квантованный** порог, а не точное сравнение `seconds <= 0.2`.
5. Есть дополнительные нижняя/верхняя проверки временного окна с runtime-параметрами. Их связь с конкретными engine cvars не восстановлена.
6. Делит прошедшие записи на две группы по dot-like величине и порогу **0.475** (RVA `0xE9ADB8`, bytes `33 33 F3 3E`; сравнение RVA `0x52B677`). В каждой группе удерживает пространственно ближайшую запись.
7. Добавляет **до двух указателей** на выбранные записи в выходной vector.

Это уже не совпадение строки `lag` или protobuf descriptor, но всё ещё **не полная lag compensation**: здесь не восстановлены создатель/удаление записей, применяемые модели и кости, teleport/discontinuity policy, rewind/restore состояния сущности и все условия валидности. Приписывать этим двум группам конкретные resolver modes нельзя.

## 3. `0x309500`: вспомогательный выбор tick/fraction

VA `0x212C3609500`, `decompiled_core/212c3609500.c`.

Функция вызывается из `0x50FB10` на RVA `0x510034` для опциональной замены временной пары. Видны:

- выбор одной из пар по byte-аргументу и добавление дробной поправки;
- нормализация через `V_modff`, перенос/заём через 1.0;
- чтение последней пары из **32-слотового** кольца: base объекта `+0x2E4`, stride 8, count/index-подобные поля `+0x3E4/+0x3E8`;
- сравнение пары с временным окном;
- подстройка части временной разницы множителем **0.01**, RVA константы `0xE98900`, bytes `0A D7 23 3C`, использование на RVA `0x3096E2`;
- выходная пара и флаг наличия результата.

Автоматический C иногда трактует представление float как integer assignment. Поля времени нельзя переносить в новый C++ по таким cast без сверки ASM. Полная семантика состояния-производителя и названия режима не установлены.

## Итог покрытия

Дополнительно декомпилированы четыре функции; всего **22 выбранных диапазона, 21 C-результат, 1 timeout**. Получение C не равно доказательству корректности. Особенно осторожно использовать `0x528B90`; для `0x767530` C отсутствует.

Подтверждены фрагменты **candidate selection → history-record filtering → aim/fire command application**. Полная политика scoring, hit testing, hitchance, damage/penetration и все rage-режимы остаются открытой задачей.
