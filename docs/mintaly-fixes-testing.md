# Патч mintaly: профили, Super Toss, Jumpbug, Molotov Color

Базовый коммит: `dfb4529e103275d0f5b0210f08c53ccd14891b45` в `flasskdev/mintaly`.
Патч подготовлен отдельно. В GitHub ничего не отправлено. Это кандидат для сборки и проверки, не проверенный игровой релиз.

## Применение

Сначала сохрани свои незакоммиченные изменения. Не используй `reset --hard` и не применяй патч с принудительным игнорированием ошибок. Файл патча можно положить в корень локальной копии репозитория.

````powershell
git rev-parse HEAD
git status --short
git switch -c fix/mintaly-config-toss-jumpbug-fire
git apply --check mintaly-fixes.patch
git apply mintaly-fixes.patch
git diff --check
````

Если `git apply --check` сообщает об ошибке, остановись. Возможно, локальная версия отличается от базового коммита. Патч следует адаптировать к твоей версии, а не перезаписывать файлы целиком.

После применения пересобери проект своим обычным способом. Патч не содержит готовую DLL и не меняет файлы сборочной системы. Новые рабочие файлы являются заголовками, подключёнными из существующих исходников. Два новых C++-файла в `tests` являются отдельными консольными тестами, не добавляй их в сборку DLL.

## Что изменено

### Профили скинченджера

Кнопка Save больше не зависит от наличия выбранного профиля. Если профиль не выбран, Save создаёт новый профиль из текущих настроек. При заполненных пяти слотах выводится явное сообщение: нужно выбрать профиль для перезаписи либо удалить ненужный. Лимит сохранён для совместимости с существующим интерфейсом.

Сохраняется индекс активного профиля. При открытии меню настройки экипировки не загружаются самовольно: сохранённый индекс определяет цель следующего Save; загрузка содержимого выполняется выбором профиля. Формат остаётся `version: 1`, добавлено необязательное поле `selected`, старые файлы читаются.

Переключение с несохранёнными изменениями требует повторного выбора. Запись идёт во временный файл с атомарной заменой; предыдущая версия хранится в `profiles.json.bak`. При ошибке записи список в памяти не переключается на несохранённое состояние. Повреждённый JSON не перезаписывается автоматически: показывается ошибка и Retry.

Путь: `%LOCALAPPDATA%\nemesis\skins\profiles.json`.

Проверки вручную:

1. На чистом профиле хранилища изменить скин и нажать Save без предварительного Create. Профиль должен появиться и сохраниться.
2. Перезапустить приложение. Проверить выбранный профиль и повторное сохранение.
3. Изменить настройки и выбрать другой профиль. Первый выбор должен предупредить о потере изменений, второй загрузить профиль.
4. Создать пять профилей, удалить активный и снова нажать Save. Проверить название, выбранный индекс и отсутствие перезаписи другого профиля.
5. Проверить переименование, одинаковые имена с разным регистром, пустое имя, CT/T, оружие, ножи, перчатки, агентов и музыку.
6. На отдельной копии файла проверить повреждённый JSON и недоступную для записи папку. Исходный файл должен сохраниться, ошибка должна быть видна.

### Super Toss

Переключатель находится в `Misc`, на основной вкладке, а не в Effects. Ключи существующих конфигов и биндов не переименованы.

Компенсация запускается после движения, quickpeek, Jumpbug и окончательной нормализации аналоговых subtick-команд. Для расчёта используется существующее предсказание движения и сохранённая движком скорость броска, если она доступна. Сохраняются уже существующие коррекция направления движения и запись углов в input history.

Направление цели для Super Toss соответствует направлению взгляда, без стандартной добавки к углу броска. Используется фактическая сила броска без округления к 0.5. В скорости учитывается стандартный коэффициент запуска 0.9 и унаследованный коэффициент скорости игрока 1.25. Их соответствие конкретной версии игры нужно подтвердить игровым тестом.

Решатель учитывает боковую и вертикальную составляющие. Если при слабом броске скорость игрока физически невозможно компенсировать, углы не подменяются. Если предсказание недоступно, в консоль однократно выводится `[super toss] prediction unavailable; angle correction skipped`, вместо использования заведомо старой скорости.

Важно: компенсируется начальное направление полёта. Это не отмена гравитации и не гарантия попадания точно в точку прицела на любой дистанции. Предпросмотр использует текущую скорость кадра, поэтому в момент изменения скорости может немного отличаться от реального броска.

Проверки вручную: броски стоя; бег A и D; прыжок+A и прыжок+D; W и S; сильный/средний/слабый бросок; включённый и выключенный air-strafe; выключенное отображение траектории. Проверить направление движения игрока, начальное направление гранаты, отсутствие NaN-углов и сообщений о недоступном предсказании.

### Jumpbug

Добавлена блокировка повторной попытки после срабатывания до двух последовательных наземных команд. Собственный подпрыгнувший персонаж больше не должен автоматически запускать следующий цикл Jumpbug. Состояние сбрасывается при смене pawn/смерти.

Отпускаются только синтетические кнопки, которыми владеет функция; удерживаемый пользователем jump/duck сохраняется. В автоматическом режиме crouch готовится заранее, но дополнительный прыжок не создаётся для обычного безопасного падения. Значение 580 используется как клиентская эвристика опасной скорости, а не как универсальная серверная константа.

Сохранены поиск узкого окна контакта и проверки свободного места/опоры. Добавлено требование реально присевшего состояния и исправлено начальное состояние duck при отпускании в момент `t = 0`. Учитывается существующая настройка `jumpbug_include_jump_steps`.

**Устранение урона от падения не подтверждено.** Серверная физика, доступность корректных трассировок и актуальность схем определяют результат. Локальный патч не даёт неуязвимость; отменять серверный урон записью клиентского здоровья он не пытается.

Проверки вручную: обычный одиночный прыжок без бинда; падение с опасной высоты; удержание бинда; отключение функции во время падения; ручное удержание Ctrl/Space; смерть/возрождение; лестница; склоны; низкий потолок; узкие края. Отдельно проверить потерю здоровья и отсутствие повторных прыжков после отпускания клавиш.

### Molotov Color

В Effects рядом со Smoke Color добавлены переключатель и выбор цвета. Значения используют уже объявленные в текущем main поля `custom_molotov` и `molotov_color`, поэтому сохраняются штатной системой конфигов.

Добавлено окрашивание RGB примитивов, владелец которых определяется как `C_Inferno`. Сохраняется исходная прозрачность, а существующий обработчик восстанавливает исходный цвет после вызова отрисовки. Цвет огня имеет приоритет над world/fullbright tint. Это не перекраска ESP-радиуса и не замена материала модели бутылки.

**Этот путь отрисовки экспериментальный.** Он работает только если огненные примитивы данной версии игры проходят через существующий `draw_scene_object` и сохраняют владельца `C_Inferno`. Если движок выводит огонь через отдельный анонимный particle-проход, цвет не изменится: потребуется отдельная интеграция с этим проходом. Подтвердить её доступность без запуска игры невозможно. Угадываемые particle offsets и глобальная перекраска всех материалов с названием fire намеренно не добавлялись.

Проверки вручную: молотов и зажигательная граната; цвет на уже горящем и новом огне; выключение функции во время горения; одновременный Smoke Color; включённый/выключенный fullbright; смена карты. Проверить, что не меняются дым, модель бутылки и ESP-радиус.

## Проверки, выполненные при подготовке

Проверены Git blob SHA-1 всех семи изменяемых существующих файлов относительно указанного базового коммита. Выполнены `git diff --check`, применение патча к чистой локальной копии этих файлов и повторная проверка полученного содержимого.

Запущены 11 Python-проверок из `tests/mintaly_patch_checks.py`: восемь проверок связей исходного кода и три проверки численной эталонной модели. В численные проверки включены 10 000 наборов направлений/скоростей, боковой прыжок и невозможный слабый бросок, обратное преобразование pitch. **Эти проверки не исполняют C++ и не подтверждают игровое поведение.**

Сборка Windows-проекта, запуск C++-тестов и проверка внутри игры не выполнялись. Среда подготовки не предоставляет компилятор C++ и игровой процесс.

## C++-тесты для запуска локально

В Developer Command Prompt for Visual Studio из корня репозитория:

````bat
cl /nologo /std:c++20 /EHsc /I. tests\throw_compensation.cpp /Fe:throw_compensation_test.exe
throw_compensation_test.exe
cl /nologo /std:c++20 /EHsc /I. tests\jumpbug_cycle.cpp /Fe:jumpbug_cycle_test.exe
jumpbug_cycle_test.exe
cl /nologo /std:c++20 /EHsc /I. tests\jumpbug_timing.cpp /Fe:jumpbug_timing_test.exe
jumpbug_timing_test.exe
````

После каждой компиляции проверь код возврата и отсутствие ошибок, прежде чем запускать соответствующий EXE. Успешные тесты завершаются с кодом 0. Не определяй `NDEBUG`, иначе проверки `assert` будут отключены.

Статические и численные Python-проверки:

````powershell
python tests/mintaly_patch_checks.py
````

## Откат

Если после применения ты ещё не редактировал затронутые строки:

````powershell
git apply -R --check mintaly-fixes.patch
git apply -R mintaly-fixes.patch
````

Это откатывает исходники, но не удаляет сохранённые пользовательские профили. Старый код понимает добавленное необязательное поле `selected`, хотя игнорирует его. Перед любой ручной заменой `profiles.json` сохрани отдельную копию файла.
