# mintaly: оптимизации и диагностика для 62bb349

База: `62bb349077e4475af3d25dba16bd8cda3bea886f`, main на момент проверки 20 сентября 2026 года.

Это частичный патч, а не подтверждённое исправление всех трёх проблем. Изменения подготовлены локально; коммит или PR в GitHub не создавался.

## Что изменено

### Производительность

1. Поиск preview-сущностей больше не сканирует все 32768 слотов каждые 100 мс при неизменной сцене. Добавление и удаление подходящих сущностей помечает список для обновления. Полный резервный обход сохранён раз в секунду; если хуки жизненного цикла недоступны, остаётся прежний интервал 100 мс. Повторные обходы после событий ограничены интервалом 100 мс.
2. Preview-косметика в матче обновляется на стадии 12 вместо стадий 0, 6, 7 и 12. Обычные обработчики оружия на стадиях 6, 7 и 12 не удалены.
3. Убран дублирующий вызов skin_sync из preview reconciliation. Список Steam ID для фоновой синхронизации перестраивается не чаще раза в 250 мс. Смена контроллера сбрасывает задержку.
4. Не обходится оружие удалённого игрока с пустым профилем, если вообще нет сохранённых оригинальных состояний, которые нужно восстановить. Аналогично пропускается ненужная локальная обработка при пустом выборе. Путь восстановления ранее применённых скинов сохранён.

Это уменьшение конкретной лишней работы, а не измеренный прирост FPS. Остальные подсистемы могут оставаться источниками нагрузки.

### Музыка в лобби

Публикация выбранного числового kit ID больше не зависит от наличия имени набора в UI-каталоге. Ранее `trigger_lobby_music` мог молча выйти до постановки запроса в очередь. Воспроизведение уже использует числовой ID, поэтому проверка имени не требовалась.

Добавлены сообщения `[lobby-music] blocked`, показывающие отсутствие хука `play_music` или сигнатур `stop_item_preview_music` / `update_bg_music`.

Это устранение одного возможного препятствия. Правильность сигнатур, аудиоконтекста и фактическое переключение трека не проверялись в CS2. Если каталог уже был загружен, эта правка может не устранить наблюдаемый симптом. Патч намеренно не угадывает адреса и не вызывает аудиодвижок из Present.

### Jumpbug

Алгоритм движения в этом патче НЕ исправлен. Добавлена диагностика, чтобы установить, почему текущий алгоритм не срабатывает, вместо очередного непроверенного изменения тайминга.

Сообщения `[jumpbug]` показывают:
- отказ из-за отсутствующего prestate, movement pawn, convar или trace-зависимости;
- некорректную геометрию hull / gravity / standable normal;
- `prepare_crouch`, `prepare_no_window` или отправленную попытку `release`;
- скорость по Z, crouch state, высоту hull, release time и результаты trace.

Обычные сообщения ограничены одним за 250 мс, отдельные release-попытки также записываются. Запись `release` означает только подготовку команды, не подтверждение её принятия сервером и не доказательство отсутствия урона. Здоровье и fall velocity не изменяются.

После диагностики можно отключить эти сообщения флагом компилятора `MINTALY_JUMPBUG_DIAGNOSTICS=0`.

## Применение

Сначала сохраните свои локальные изменения. Патч рассчитан на указанную базу, а не на произвольную последующую версию main.

````sh
git rev-parse HEAD
git status --short
git switch -c fix/runtime-followup
git apply --check /path/to/mintaly-runtime-followup.patch
git apply /path/to/mintaly-runtime-followup.patch
python -m unittest discover -s tests -p '*checks.py' -v
````

Затем соберите проект привычным для него Windows toolchain. Команда сборки здесь намеренно не выдумывается. Успешный `git apply` или Python-тест не означает успешную компиляцию C++.

## Что проверено

- SHA исходных blob для шести изменённых C++ файлов и заголовков сверены с деревом указанного коммита.
- 61 Python-проверка прошла на загруженном наборе исходников, включая структурные проверки проекта и уже существующую численную модель броска гранаты.
- Добавлены 7 структурных регрессионных проверок. Существующая проверка количества preview-предикатов уточнена до области `refresh`, поскольку такой же предикат теперь нужен и обработчику событий.
- `git diff --check` и применение патча к чистой локальной базе проверены.

НЕ выполнялись: компиляция C++, запуск C++ unit tests, загрузка DLL в игру, измерение FPS, подтверждение смены музыки или предотвращения fall damage. Python-проверки не проверяют совместимость с игровым бинарником.

## Воспроизведение и лог

Проводите проверку на локальной/тестовой карте. Сравнивайте одинаковую сцену, разрешение, лимиты FPS и закрытое меню, сначала без новой DLL, затем с ней. Отдельно проверьте отключение косметики после её применения, подбор оружия, смену команды и карты: оригинальные состояния должны восстанавливаться.

Для музыки: переключите стандартный набор на A, затем B и обратно на стандартный. Проверьте сценарий подключения DLL, когда музыка уже играет, и возврат из матча в лобби.

Для jumpbug: включите функцию, выполните несколько падений с одной точки и запишите, при каких попытках появился урон. По возможности укажите версию игры, тип сервера и активные movement-функции.

Существующий логгер проекта пишет в:

`%TEMP%\nemesis-<PID>\mintaly_init.log`

Путь подтверждён кодом `utilities/diag.hpp`. Пришлите только строки `[jumpbug]`, `[lobby-music]` и соответствующие сообщения о недоступных хуках за время воспроизведения. Полный лог может содержать лишние идентификаторы аккаунта или сведения о локальной системе, поэтому сначала просмотрите его.

Для извлечения в PowerShell, подставив PID процесса:

````powershell
Select-String -Path "$env:TEMP\nemesis-<PID>\mintaly_init.log" -Pattern '\[jumpbug\]|\[lobby-music\]|unavailable hook'
````

Без этих runtime-данных патч нельзя честно считать окончательным исправлением музыки и jumpbug.
