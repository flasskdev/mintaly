# Исправления CFG, биндов, onshot, jumpbug и скинченджера

База: `flasskdev/mintaly`, коммит `7cbc851d03f40f35f10e32a8fb530265e5c2ebd9`.
Изменения подготовлены локально, не закоммичены и не отправлены в GitHub.

## Применение

Перед обновлением сделайте резервную копию общих CFG. Если нужный набор скинов существует только в отдельном профиле скинченджера, в старой версии загрузите его и сохраните в общий CFG. Старый `profiles.json` патч не удаляет, но новая версия его не читает.

В корне репозитория на указанном базовом коммите:

````sh
git apply --check mintaly-fixes.patch
git apply mintaly-fixes.patch
````

Архив содержит только изменённые и новые файлы, не полный репозиторий. Альтернатива патчу: скопировать содержимое каталога `changed-files` в корень рабочей копии. Не применяйте оба способа последовательно. При отличающейся версии сначала проверьте патч, не перезаписывайте новые изменения вслепую.

## 2. CFG и бинды

В обоих загрузчиках, полном CFG и delta/share, сброс старых биндов выполняется до загрузки значений. Так старое базовое значение активного слайдера не может перезаписать значение из нового CFG. Загрузка списка биндов заменяет его целиком, включая пустой, отсутствующий или некорректный список. Сброс CFG в меню также очищает бинды.

Бинды зарегистрированных числовых настроек теперь сохраняют стабильный ключ поля `category/name`, а не только идентификатор элемента интерфейса. Их указатели регистрируются при инициализации CFG, поэтому восстановление новых биндов не требует предварительного открытия каждой вкладки. Проверены регистрация семи числовых/массивных полей и категории всех десяти переключателей в `ragebot::weapon_group`, а также инициализация групп и индивидуального оружия. Отдельный Windows integration-тест покрывает round-trip всех экземпляров этих настроек.

При сохранении активного слайдер-бинда пишется базовое значение, не временный override. Базовое числовое значение хранится без потери точности `int`. Состояние удерживаемой клавиши не сохраняется как постоянное состояние переключателя. При загрузке очищаются runtime-состояния, подавляется ложное повторное переключение уже удерживаемой клавишей, закрываются старые popup-редакторы. Проверяются диапазоны клавиш, режимы и конечность числовых значений.

Открытие Rage/Legit больше не включает `Custom Weapon Settings` самопроизвольно из-за наличия бинда: сохранённое `override=false` остаётся выключенным. Для индивидуального бинда надо явно включить индивидуальные настройки оружия.

### Совместимость

Обычные ключи CFG не переименованы. Старые slider binds, у которых был только UI-ID, мигрируют при показе соответствующего элемента управления. После загрузки старого CFG откройте вкладки и группы оружия с такими биндами, затем пересохраните CFG. Если UI-ID уже изменился относительно версии, в которой сделан старый файл, автоматически восстановить связь по одному ID нельзя: такой бинд потребуется назначить заново. Новые CFG используют стабильные ключи и не имеют этой зависимости. Обратная совместимость новых slider binds со старой сборкой не обещается.

Аудит и исправления гарантируют наличие путей сериализации на уровне исходников, но не заменяют проверку поведения каждого игрового режима. Бинды динамических пользовательских полей вне реестра числовых настроек остаются legacy/UI-ID; при замене CFG старые указатели таких полей отсоединяются.

## 3. Onshot-чамсы после попадания

Единственная точка запуска перенесена в обработчик подтверждённого `player_hurt`, после проверки локального атакующего и жертвы, при положительном уроне. Удалены запуски от команды Rage и от одного лишь выстрела револьвера. Снимок костей берётся независимо от включённого Rage/lag compensation.

Длительность по умолчанию составляет **0,25 с**, настройка `duration` допускает **0,05–5,00 с**, интерфейс показывает доли секунды. Старый ключ `chams onshot / fade time` сохранён. Таймер начинается в момент события попадания и работает по монотонным часам. При следующем попадании по той же цели снимок и таймер заменяются.

Создание/удаление графических объектов остаётся в frame-stage. Время истечения проверяется на render-start, объект рисуется через свой callback, а не только при отрисовке живой модели. Для ghost-объекта отключён дополнительный незатухающий original pass. В очереди проверяется handle поколения сущности. Если кости или сущность уже недоступны, эффект безопасно пропускается.

Материалы и слои onshot по-прежнему настраиваются существующими контролами. Для видимого эффекта должен быть включён нужный слой чамсов.

## 4. Jumpbug

Устранена зависимость от скрытого `edgebug jump steps`: общий blank-profile сбрасывал этот флаг, и функция могла отправлять только отпускание приседа, без прыжка. Теперь при найденном допустимом окне всегда формируется упорядоченная пара unduck/jump.

Подготовка приседа начинается при снижении, без ожидания вертикальной скорости -200. Probe перенесён на 1,5 единицы в пределах двухъединичного окна категоризации земли; допускается касание пола при нулевой доле support trace, только если проверка свободного standing hull прошла. Сохранены проверка опоры/потолка, упорядоченные subticks, предварительное выделение всех событий и освобождение только кнопок, которыми владела функция.

**Это исправление обнаруженных ошибок, а не подтверждение неуязвимости к урону.** Windows-сборка, локальный prediction и сервер CS2 здесь не запускались. Корректность сигнатур, движения на склонах/подвижной опоре, серверных настроек и фактическое отсутствие fall damage нужно проверять в игре. Записи здоровья и fall velocity не используются. Существующая диагностика `[jumpbug]` оставлена.

## 5. Скинченджер

Удалены отдельное хранилище профилей, dropdown, создание, сохранение, переименование, удаление и загрузка отдельных cosmetic configs. Освободившееся место используется под preview. Сами настройки скинов, CT/T-наборы, агенты, custom agents и музыка остались в общей CFG-системе.

## Проверки

Выполнены 85 Python-проверок исходников и имеющейся численной модели из пяти наборов; все прошли. Это не исполнение изменённого C++ и не игровой тест. `git diff --check` и проверка применения патча на восстановленной базе также выполнены. Текстовый баланс скобок проверен отдельно, но он не доказывает компилируемость.

````sh
python tests/fix_source_checks.py

python tests/lobby_cosmetics_checks.py
python tests/mintaly_patch_checks.py
````

Добавлен `tests/config_bind_roundtrip.cpp`, integration-тест реальных функций CFG/xui для Windows, с зависимостями основного проекта. Его надо подключить как отдельный тестовый executable, исключив DLL entry point, и связать с реализациями xui/xdraw и зависимостями проекта. Он **не компилировался и не запускался** в этой среде; это не автономный Linux-тест.

### Обязательный smoke-test перед использованием

1. Сохранить A с разными Rage-настройками для групп и оружия, обычными toggle/hold-биндами и slider binds. B должен иметь другие значения, другой набор биндов и часть выключенных weapon overrides.
2. Зажать slider bind в A, сохранить A и загрузить B. После отпускания клавиши проверить, что значение B не заменилось значением A. Повторить A → B → A, reset и import/share, включая файл без `sb` и с пустым `sb`.
3. Перезапустить программу, загрузить новый CFG и проверить бинды до открытия Rage-вкладки. Затем проверить старый UI-ID CFG, миграцию после открытия вкладок и повторное сохранение.
4. Проверить onshot на попадании и промахе, ручной стрельбе, Rage, револьвере, убийстве и повторном попадании. Проверить 0,05/0,25/1,00 с и смену карты.
5. Проверить jumpbug на одинаковой высоте многократными падениями, с hold/toggle, bhop и duckpeek, затем на склоне и под потолком. Сравнить фактический урон на сервере и `[jumpbug]`-диагностику. Не считать один успешный прыжок доказательством исправления всех случаев.
6. Проверить сохранение и восстановление CT/T-скинов, агентов и музыки только общим CFG.
